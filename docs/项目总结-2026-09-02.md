# kgx 项目总结（2026-09-02）

> kgx = Knowledge Graph eXtraction：面向长篇小说的关系抽取与知识图谱构建**框架**。
> 以《红楼梦》120 回全书验证：**零手写人物先验**，对 266 条金标准 F1 56.6%（P 47.7 / R 69.5），
> 随机抽检真实精度 **96%**（48/50，95% CI 86.5–98.9%）；超过前代 v1（手写实体表+先验规则）的 45.4%。
> 代码 ~1600 行（kgx/ 14 模块），全书一次运行约 130 次 LLM 调用、成本 ≈ 50 元人民币等值积分的 1/3。

---

## 1. 方法：管线九步

```
原文 → ①切章打包 → ②实体预扫描 → ③滚动登记簿 → ④整块抽取+补抽 → ⑤程序校验
     → ⑥程序化归并 → ⑦聚合计票 → ⑧LLM 分组复核 → ⑨规则推导 → 图谱 + 分层评估
```

| 步 | 做法 | 借鉴/出处 |
|---|---|---|
| ① 切章打包 | 章节正则 + **章号连续性校验**（防正文伪标题）；3 回/2.4 万字一块 | 自研（踩坑产物） |
| ② 预扫描 | jieba 词性/n-gram/对话归属/标题/命名模式六路候选 + 一次 LLM 分类别名分组 | AI-Reader-V2 |
| ③ 登记簿 | 实体清单（规范名/别名/身份）随抽取滚动更新，作为每块的上下文 | AI-Reader-V2 |
| ④ 抽取 | 过程式 prompt（先登记后抽取再查漏），关系端点必须来自登记簿；补抽一轮 | kg-gen + GraphRAG gleaning |
| ⑤ 校验 | **零 LLM**：关系闭集、类型约束、方向自动翻转、证据必须逐字出自原文且提及双方（1→3 句窗检索补证） | 自研，防幻觉核心 |
| ⑥ 归并 | 程序化：姓+名全名补全、重复实体合并、**同名多姓歧义守卫** | 自研（事故产物） |
| ⑦ 聚合 | 方向规范化、**按不同证据句计票**（防重复输出灌票）、functional 冲突裁决 | 自研 |
| ⑧ 复核 | 按实体分组打包裁决 + 三条护栏（否决须给类别/高票保护/方向类改翻转）+ 开思考 | OneKE Reflection + v1 教训 |
| ⑨ 推导 | schema 声明式规则前向推理（同父→兄妹、父辈堂亲→堂亲…），带推导链与最弱票置信 | 自研 |

**防幻觉三板斧**贯穿全线：关系闭集约束（只能用 schema 声明的 13 种）、证据强制（每条关系带逐字原文引用，程序验证）、投票聚合（多处独立证据才是高票）。

## 2. 核心设计决策

1. **schema 驱动，领域知识单点进入**：实体类型、关系定义、易混判据、推导规则全部只写在 `schemas/<书>.yaml`；代码里出现任何具体人物知识即违规。换书 = 换 yaml + 换金标准，`kgx/` 包零修改。
2. **评估与管线物理隔离（红线）**：金标准与评估别名表放 `gold/`，只被 evaluate 引用；管线永远看不见考卷。金标准可放心扩充而不构成作弊。
3. **可解释分层**：每条关系标来源层（文本抽取 / 模型知识 / 推导），层间精度递减、下游按需取用；推导带完整前提链。
4. **单模型 + provider 抽象**：`Gemini` / `OpenAICompat` 同接口，磁盘缓存按 (模型+请求) 哈希——重跑下游零成本，这是两天内十几次返工没有烧穿预算的根本原因。
5. **断点续跑 + 自愈**：块级进度落盘、失败不记为完成、外壳脚本自动重拉；全书跑在免费公测网关上无人值守完成。

## 3. 遇到的问题与解决（时间线实录）

### 3.1 资源层
| 问题 | 表现 | 解决 |
|---|---|---|
| Gemini 免费档配额 | 每日 20 次，全书需 130 次，停摆 10 天 | 迁移商汤 Token Plan（OpenAI 兼容网关），积分核算后确认非约束 |
| 模型默认开思考 | 16k 输出全烧在 reasoning，正文为空 | `reasoning_effort:"none"`（实测 `"low"` 无效） |
| 共享池 TPM 429 | 与本方用量不成函数关系（闲置后小请求也撞） | 按 token 节流防连发 + 指数退避不退出；**结论：是免费公测的代价，不硬扛** |
| 全局代理断连 | `ProxyError` 伪装成网关不稳 | 国内服务直连（`trust_env=False`），Gemini 保持走代理 |
| 积分成本 | kimi-k3 单价 ≈ DeepSeek 50 倍 | 单块探针对比后弃用；成本表进报告 |

### 3.2 模型行为层
| 问题 | 表现 | 解决 |
|---|---|---|
| 输出截断 | 模型吐 pretty JSON 撞 16k 上限 | 紧凑 JSON 指令 + 上限 32k + **截断 JSON 抢救解析**（保留已完整对象） |
| 内容审查拒答 | 整块 `content_filter`（模型侧、有随机性） | 逐级拆段重试：块→单章→切半→1/4，最终**零段落丢失** |
| 重复输出循环 | 一块 418 条只有 21 种；或笛卡尔积式假关系 | 按"原始/去重三元组"与"原始/去重证据句"双比值判定，多章块拆章重抽 |
| 抽取产出不稳 | 网关瘦响应，一块只出 10 条 | 低产出守门（密度<1.2 条/千字换措辞二读）+ 空响应重试 |
| 复核结论与理由打架 | ok=true 但理由写"不成立" | 矛盾裁决标存疑保留，不采信也不删除 |

### 3.3 数据与评估层
| 问题 | 表现 | 解决 |
|---|---|---|
| 切章伪标题 | 第五回正文"第四回中既将…"被当标题，章号全体偏移 1 | 章号必须连续递增（中文数字解析），框架级修复 |
| **宝玉→甄宝玉归并事故** | "姓+名"归并规则把主角并进同名配角，561 条错标，复核"正确地"大量否决 | 同名多姓候选视为歧义整体跳过；登记簿从 git 恢复。**教训：同名不同姓不等于同人** |
| LLM 归并失效 | 607 实体一次调用，模型原样回吐 | 程序化归并替代（全名补全 + 重复合并），LLM 归并降级为可选 |
| 金标准命名错位 | 考卷写"贾探春/贾家（宁国府）"，原文从不出现 | 金标准 v2：评估专用别名表 + 按条变体匹配 + 范围声明；扩充 85 条均经原文有据验证 |
| 票数灌水 | 同一三元组同块重复 21 次 = 21 票 | 票数按不同证据句去重 |

## 4. 消融与审计：每个决定的数字背书

| 实验 | 结论 |
|---|---|
| 复核思考开/关（D−B） | **+2.6~3.1 F1**，模型知识补充错误率 10/33→1/67；代价：慢 10 倍、贵 30 倍 → 出版跑开、日常关 |
| 复核护栏（B−A） | F1 持平，但方向翻转救回 44 条真事实，错误形态更干净 |
| 无合格证据 682 条抽样 40 | 多为"真关系证不出"（模型写结论不引原文 45%、主语省略 33%、别名缺口 22%），真幻觉少数 → **不放宽标准**，作为证据强制设计的已知代价写入报告 |
| 复核误杀复查 | 砍 278 个候选仅误杀 10 条真项（事故修复后） |
| 真实精度抽检 50 条 | **96%**；对金标准 P=46.4% 是覆盖性低估的直接证据（两个口径并列报告） |
| 模型选型探针 | kimi-k3 质量略优但 50 倍价；flash-lite 不可用；glm-5.2 12 倍价无优势 → deepseek-v4-flash |

## 5. 结果汇总

**漏斗**：原始 2,767 → 校验 1,895 → 聚合 612 → 复核 295（+补充 67）→ 推导 +49 → **图谱 386 条**，登记簿 607 实体。

| 层 | P | R | F1 |
|---|---|---|---|
| 文本抽取 | 46.4% | 53.4% | 49.6% |
| +模型知识 | 46.0% | 59.0% | 51.7% |
| **+推导** | **47.7%** | **69.5%** | **56.6%** |

对照：v1（手写实体表+先验）45.4；v2 首跑（修复前）35.8。真实精度（抽检）96%。
成本：全书主跑 130 余次调用、~3.6M token；两天全部实验共 ~2.5 万积分（周免费额度 600k 的 4%）。

## 6. 含金量在哪里

1. **零先验超手写基线**：v1 靠 60 人手写实体表和先验规则拿 45.4；v2 把全部领域知识压进一页 yaml，拿 56.6。"框架换书即用"不是口号，是被数字验证的架构选择（三国演义文本已备好待迁移）。
2. **每个设计决定都有实验背书**：思考值几个点、护栏值什么、证据强制丢了什么、金标准为什么低估——全部有消融/审计数字，不是"我觉得"。这是分析师式的"提问→假设→取数→结论"闭环。
3. **对抗真实环境的工程可靠性**：免费公测网关的共享池限速、内容审查、模型循环、连接抖动——全部程序化消化，全书无人值守跑完。缓存/断点/自愈的设计让十几次返工近乎零成本。
4. **成本意识**：模型选型有单价核算（每条有效三元组 2 vs 58 积分），思考的性价比有账可查，"企业视角的成本问题"有正面回答。
5. **诚实的评估方法论**：管线与考卷物理隔离；金标准扩充声明范围、逐名有据验证；AI 标注如实注明并留人工复核点；两个精度口径并列而非挑好看的报。
6. **可复述的事故复盘**：宝玉→甄宝玉事故从模型的一个"合理"别名开始，经程序规则放大，被复核"正确地"掩埋——完整的因果链和修复（歧义守卫）是面试里最有说服力的 debugging 故事。

## 7. 已知局限与后续

- 家族分支（宁/荣）文本证据不支持区分，金标准按同族计；表/堂亲推导受制于始祖级前提（贾演/贾源）不可抽取；
- 主仆归属是残余错误的主要形态（"听差/随行"误判为名下），抽检 2/50 均属此类；
- 真实精度标注者为 AI，方法学上弱于人工（4 条边界项已标出待人工复核）；
- ~~三国演义迁移验证~~ **已完成（09-03）**：仅新增 2 个数据文件、kgx/ 零修改，一夜无人值守跑完 120 回；文本层召回 73.2%（君臣 93%）、抽检真实精度 91%。详见 docs/待办-2026-09-01.md §10。
- 后续：面板接入 v2 输出。（隶属规则单一势力约束已于 09-03 实施：推导 762→322）
