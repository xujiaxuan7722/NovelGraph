# 参考项目借鉴笔记（面向 v2 框架设计）

阅读对象（2026-08-21 精读源码）：
- **kg-gen**（stair-lab，NeurIPS'25）`git clone --depth 1 https://github.com/stair-lab/kg-gen`
- **AI-Reader-V2**（mouseart2025，中文小说分析）`git clone --depth 1 https://github.com/mouseart2025/AI-Reader-V2`
- **GraphRAG**（microsoft）`git clone --depth 1 https://github.com/microsoft/graphrag`
- 另参考（仅读文档）：iText2KG/ATOM、Graphiti、OneKE

全文按 **v2 的模块**组织：每个模块先说"谁做得好、具体在哪个文件"，再说"照搬什么、改什么、不要什么"。

---

## 0. 总评：三者各自的长处

| 项目 | 最强的一点 | 最弱的一点 |
|---|---|---|
| kg-gen | 代码最干净；实体表约束关系抽取；`entity_clusters` 别名映射表示；分簇→簇内 LLM 判重 | **零溯源**（三元组不带证据/位置）；英文分句/词形处理对中文失效 |
| AI-Reader-V2 | 中文小说实战经验最厚：预扫描词典、Union-Find 多层保险别名归并、幻觉过滤回原文、关系类型归一+聚合决策、人工覆盖层 | 关系无二次验证、evidence 不回核、方向无校验；名著别名靠硬编码先验 |
| GraphRAG | 工业级管线分层；**gleaning 多轮补抽**；同名实体描述合并再摘要 | 面向 RAG 不面向精确三元组；token 消耗大 |

## 1. 模块：schema / 关系类型体系

**学 AI-Reader-V2 的"推荐词汇 + 归一表 + 大类映射"三层结构**

- prompt 里给**推荐类型词**而不是硬枚举（`extraction/prompts/extraction_system.txt`）：血亲/亲密/未遂/师承/社交/敌对六组，并写明易混对的判据（师兄弟 vs 同门 vs 结拜兄弟）和常见错误清单；
- `services/relation_utils.py: _RELATION_TYPE_NORM` 做变体归一（养父子→父子、拜把子→结拜兄弟）；`_RELATION_CATEGORY` 再映射到 6 大类。

**照搬**：三层结构 + "性别区分血亲"的规则（"生得一女→父女不是父子"）+ 常见错误清单写法。
**改**：我们走 schema.yaml 声明式——类型、方向、对称性、functional 约束、推导规则都在一个文件，prompt 由 schema 自动生成，这比 AI-Reader-V2 的"prompt 推荐 + 字符串归一"更可迁移、更可评估。
**不要**：开放式关系类型字符串（它们自己也承认跨章一致性只能靠投票兜）。

## 2. 模块：实体预扫描 + 滚动登记簿

**学 AI-Reader-V2 的 `EntityPreScanner`**（`extraction/entity_pre_scanner.py` + `prescan_prompts.py`）

零 LLM 成本的六路候选合并：jieba `nr/ns/nz` 词性 → 2-4 字 n-gram（freq≥5，去被长词覆盖的子串）→ **对话归属正则**（`"…"X道` / `X道："…"`）→ 章节标题 → **命名模式**（`叫作|名叫|绰号|外号|人称|又名|唤作…`，命中者绕过频次门槛）→ 后缀推类型。然后一次 LLM 调用对 top150 分类 + 别名分组，并明确写"同姓不等于同人""亲属关系不是别名"。`_merge_llm_results` 只接受候选里存在的 alias（防幻觉加人）。

**照搬**：整套 Phase 1（纯 Python，可直接移植）；Phase 2 的 prompt 原文；"词典注入抽取 prompt 时标注'需文本确认'"的措辞。
**改**：红楼梦的对话归属正则要加"X笑道/X冷笑道/X因说道"等变体；称谓消歧（二奶奶/凤丫头）不能靠预扫描解决，要靠滚动登记簿。

**学 AI-Reader-V2 的 `ContextSummaryBuilder`**（`extraction/context_summary_builder.py`）——这就是"滚动登记簿"的实战版本

传给下一章的不是情节摘要，而是**结构化清单**：最近 20 章活跃人物（名+≤3 别名）、涉及活跃人物的已知关系（每对只留最新类型）、已知地点层级、预扫描高频词。长度按模型窗口插值（6000→18000 字），超长截断。

**照搬**：结构化清单而非摘要的思路；活跃窗口；按窗口预算裁剪。
**改**：我们要加"每个人物一句话身份"（这是称谓消歧的关键，AI-Reader-V2 没有）；并让模型**输出对登记簿的增量更新**（新人物/新别名/身份修正），而不只是单向注入。
**参考 Graphiti**：新片段进来先和已有图比对去重、冲突不删而标失效——我们的"已知关系"冲突处理可借这个思路（保留两版并标注章回，复核时再裁）。

## 3. 模块：通读抽取 prompt

**学 GraphRAG 的 prompt 骨架 + gleaning**（`packages/graphrag/graphrag/prompts/index/extract_graph.py`、`index/operations/extract_graph/graph_extractor.py`）

- 实体带 `description`、关系带 `description + strength`，用分隔符格式而非 JSON（小模型更稳）；
- **gleaning 循环**：抽完后追加 `CONTINUE_PROMPT`（"MANY entities and relationships were missed… Add them below using the same format"），再问 `LOOP_PROMPT`（"Answer Y/N: still missed?"），最多 `max_gleanings` 轮。

**学 kg-gen 的两阶段约束**（`steps/_1_get_entities.py` → `_2_get_relations.py`）：先抽实体表，再用实体表约束关系的 subject/object（litellm 路径用 `Literal[tuple(entities)]` 硬约束；dspy 路径失败时走 `FixedRelations` ChainOfThought 修正 + `in entities` 过滤）。另外 kg-gen `relations.txt` 要求模型在 `<analysis>` 里逐实体引原文再找关系、最后检查孤立实体——过程式 prompt 值得抄。

**照搬**：gleaning 循环（对免费小模型召回提升明显、成本低）；"关系端点必须来自实体表"的硬约束；过程式 prompt（先逐实体引证据→再定关系→再查孤立）。
**改**：证据字段必须保留并校验（kg-gen 把 `<analysis>` 丢了，我们要把 evidence 做成一等字段）；输出用 JSON（我们已有加固解析器）。

## 4. 模块：别名归并 / 实体消歧

**学 kg-gen `utils/llm_deduplicate.py`**：KMeans 分簇（簇≤128）→ 簇内对每个 item 用 BM25+embedding 混合召回 top16 候选 → 一个 Signature 返回 `duplicates + alias`；结果落成 `entity_clusters: dict[标准名, set[别名]]`。
**学 AI-Reader-V2 `services/alias_resolver.py` + `services/name_authority.py`**：Union-Find 合并词典别名和各章 new_aliases，四层保险——相似名冲突拒绝（阮小二 vs 阮小七）/ 都是主实体拒绝 / 大组延迟需 ≥3 章证据 / 合并后 >20 拒绝；`alias_safety_level` 三级安全（亲属词、泛称、含"的"、姓+称谓后缀等硬拦，**整张词表可直接拿走**）；规范名选择 `pick_canonical`（"3 字全名 vs 2 字简称 10 倍阈值"）。

**照搬**：AI-Reader-V2 的安全等级词表 + Union-Find 多层保险（规则层）；kg-gen 的"候选召回 + LLM 判重 + clusters 表示"（LLM 层）。两者正好互补：规则层管安全，LLM 层管召回。
**不要**：AI-Reader-V2 的 `person_knowledge_prior.py`（按书名硬编码"孙悟空/行者/大圣…"别名组）——这正是我们明确禁止的实例知识注入。我们的解法是滚动登记簿让模型**在读的过程中**把别名读出来。
**改**：kg-gen 的 BM25 `lower().split()` 和 `inflect` 单数化对中文无意义，embedding 模型换中文的（bge-small-zh 等）或直接用 LLM 判重。

## 5. 模块：证据校验 / 幻觉过滤

**学 AI-Reader-V2 `services/hallucination_filter.py`**：把全书拼成一个字符串，实体（规范名或任一 ≥2 字别名）字面不出现即判幻觉。零 LLM，简单有效（它是为了修"小模型把别的书的人写进来"）。

**照搬**：思路。我们已有更强的版本（证据必须出自原文且同时提到双方、不合格则回原文检索补证）。
**改**：AI-Reader-V2 只过滤人名不过滤关系、evidence 不回核——这是它的明显短板，我们的证据一等字段 + 回核正好补上，报告里可以作为对比点。

---

## 6. 模块：聚合与冲突裁决

**学 AI-Reader-V2 `services/entity_aggregator.py: aggregate_person`**：同一 pair 的类型决策——血亲/亲密类型需 ≥3 章证据才锁定；亲密若 ≥3 倍于血亲则覆盖（宝玉↔黛玉 兄妹1 vs 恋人58）；"兄弟"但不同姓→改"结拜兄弟"；具体类型优先于泛型；再频次投票。`profile_quality_checker.fix_relation_mutations` 把 A→B→A 振荡拉平。

**照搬**：分章证据链（`RelationStage`）+ 多章一致性要求；具体优先于泛型。
**改**：我们的 functional 约束（一父一母）和对称关系归一放在 schema 里声明，比写死在聚合代码里更通用。

---

## 7. 模块：全局复核 / 反思

**学 OneKE 的 Reflection Agent + 案例库**：抽取后由反思代理对照历史案例检查一致性。
**学 GraphRAG 的"同名实体描述合并后再让 LLM 写总结"**：多章对同一人物的描述合并成档案——这就是登记簿的"人物一句话身份"来源。

**照搬**：我们已有的成组复核就是 Reflection 的形式；加上"合并描述→生成档案"可以让复核时模型有更完整的人物画像。

---

## 8. 模块：评估

**学 kg-gen 的 MINE 基准**（`experiments/MINE/`）：没有金标准时评"图谱信息量"——用图谱回答一组由原文生成的事实问题，看覆盖率。
**学 AI-Reader-V2 的金标准闭环**：`data/review/标注指南.md`（每本 7 个文件：层级树/80 人物/40 别名组/80 关系对/5 章抽检）→ 人工审核 JSON → `tests/test_golden_standard.py` 作 pytest 回归守卫；`eval_dashboard.py` 算人物 precision、关系 type/category accuracy、别名 group accuracy。

**照搬**：标注指南的文件结构（可直接套）；"人工审核 JSON → 回归测试"闭环；MINE 式的问答覆盖评估作为无金标准时的补充。
**改**：它们都缺系统性 recall 和端到端 P/R/F1，我们保留现有的 P/R/F1 脚本。

---

## 9. 模块：人工覆盖

**学 AI-Reader-V2 `entity_override_store` + `_apply_user_overrides`**：支持 `alias_merge / alias_split / entity_rename`，每次重建都重放，并记录与自动结果的漂移供 UI 标"冲突"。

**照搬**：面板里加"合并/拆分/改名"三个操作 + 漂移记录——这是"人在回路"的正规做法，不是兜底（操作有记录、可回滚、和自动结果分开统计）。

## 附：我们相对这三者的差异化贡献点

1. **证据一等字段 + 回原文核验 + 检索补证**：三者都没做到关系级溯源；
2. **称谓消歧的滚动登记簿（模型自己读出别名，不靠硬编码先验）**：AI-Reader-V2 靠硬编码，kg-gen 靠事后聚类；
3. **schema.yaml 声明式本体 + 推导规则**：三者要么开放字符串，要么 Pydantic 写死；
4. **分层来源（文本抽取 / 模型知识 / 推导）+ 分层评估**：没有项目把"模型知道"和"文本里有"分开统计。
